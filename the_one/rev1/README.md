# About: The One rev1

## 1. Layout

This is the first time I start this kind of project. Therefore, I wondered what is the best way to create a "standard" layout for my keyboard, which can be reused later for PCB design or 3D modeling.

After researching for a while and tried out some options, I decided that **Ergogen** is a suitable tool for me.

> !!! ALERT: AI-generated content below :D !!!
>
> Ergogen is a tool used to programmatically design ergonomic keyboards.
> 
> Instead of drawing keys manually, you describe your keyboard in codes (YAML) and Ergogen will generate for you:
> - Key layout (positions, spacing, rotation)
> - Plate layout (for case / switch plate)
> - PCB footprints (for KiCad)
> 
> This means in order to use this tool, it is required to have some basic understanding about the YAML syntax.

You can access this tool using the [Ergogen web-based UI](https://ergogen.xyz).

To understand the structure of Ergogen YAML files, I suggest you to have a look at their [documents](https://docs.ergogen.xyz/config-overview) first.

You can find the Ergogen files in [1_layout](./1_layout/) folder, including:
- `config.yaml` : contains the YAML codes (which you put on the left panel of Ergogen tool) which define the keyboard layout.
- DXF files in `outlines` folder : CAD-format files which are generated by Ergogen, based on the definitions in `config.yaml`. I will use these files for PCB designs ad 3D modeling.

> While using Ergogen, I realized that it can automatically create a KiCad PCB file with necessary footprints or edge cuts of your layout, by using the `pcbs` block.
>
> However, the intention for this project was to learn as much as I could, and to have a full capacity in custommizability.
> Therefore, I want to avoid this kind of 'automation', not because Ergogen feature was bad or limited, but because ... I want to :D
> 
> So, I decided to skip this block in the YAML file and started a new KiCad project instead.

## 2. Schematics & PCB

As mentioned above, since I decided not to use Ergogen's PCB auto-generated feature, I used **KiCad** software to create the schematics as well as the PCB for the keyboard.

My KiCad software version: 10.0.0

Big thanks to the following open-source repositories, which provided me awesome assets in this KiCad project:
- Raspberry Pi RP2040 symbols, footprints and 3D models: **KiCad-RP-Pico** by ncarandini (TPCWare) [Github](https://github.com/ncarandini/KiCad-RP-Pico)
- Standard keyboard switches footprints and 3D models: **kiswitch** [Github](https://github.com/kiswitch/kiswitch/tree/main)

You can find the KiCad project as well as related resources in [2_pcb](./2_pcb/) folder.
- For external symbol libraries, I stored them in [symbols](./2_pcb/symbols/) folder.
- For external footprint libraries, I stored them in [footprints](./2_pcb/footprints/) folder.
- For external 3D assets, I stored them in [3dmodels](./2_pcb/3dmodels/) folder.

The above libraries were imported into the KiCad project using relative path `${KIPRJMOD}`, so they should work in your computer.

### a. Concepts

My plan was to use two Raspberry Pi RP2040 development boards for left and right sides.

The left-side board is powered from the connected PC through a USB-C cable, then shares the VBUS line with the righ-side board.

The communication between these two boards will be UART, where left-board acts as a **master node**, which:
- scans which keys on the left side are pressed. 
- receives key pressed signals from the right-side board.
- sends key press status to the PC.

The right-board acts as a **slave** node, which:
- scans which keys on the right side are pressed.
- sends key press status to the left-board.
- supplies power to e-Ink display.
- sends commands and data to the e-Ink display with the SPI protocol.

Each key is registered and recognized by a row-column matrix. You can learn more about the matrix [here](https://docs.qmk.fm/how_a_matrix_works).

The e-Ink display I selected for this keyboard is **Waveshare 1.54inch e-Paper Module (SKU 12955)**.
